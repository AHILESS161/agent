# Интеграция с Open API Роспатента

## Публичный режим без API-ключа

Для предварительного поиска можно включить адаптер публичной страницы
<https://searchplatform.rospatent.gov.ru/trademarks>:

```dotenv
FIPS_PROVIDER=rospatent_public
FIPS_PUBLIC_BASE_URL=https://searchplatform.rospatent.gov.ru/
FIPS_PUBLIC_DATA_SOURCES=trademarks,known_trademarks,international_trademarks
FIPS_PUBLIC_MAX_RESULTS=100
FIPS_PUBLIC_PAGE_SIZE=50
FIPS_PUBLIC_MIN_INTERVAL=0.75
```

Адаптер повторяет анонимный read-only запрос самой страницы через Engine.IO /
Socket.IO. Он не обходит авторизацию, не отправляет заявки и ограничивает частоту
запросов. Результат включает регистрации и опубликованные заявки, номера, даты,
правообладателей, классы МКТУ и доступные изображения.

Это не опубликованный контракт API: адреса и формат могут измениться без
предупреждения, а полнота выдачи не гарантирована. Поэтому отчёты помечают такой
поиск как `limited`; его нельзя считать юридическим заключением или заменой
профессионального поиска. Официальный вариант с договорным доступом описан ниже.

## Технический протокол публичного режима

Публичная страница является React-приложением и не содержит результаты поиска
в HTML. Адаптер не разбирает разметку и не запускает браузер: он повторяет
анонимный read-only обмен самой страницы через Engine.IO v4 / Socket.IO:

- транспорт: HTTP long-polling, endpoint `/socket.io/`;
- namespace: `/search`;
- событие запроса: `send_task`;
- сервис: `esi-search`, путь `/api/v1/search`;
- событие результата: `send_results`;
- источники: `trademarks`, `known_trademarks`, `international_trademarks`.

Поддерживаются точный (`match`) и нечёткий (`fuzzy`) поиск, фильтр классов
МКТУ и разделение регистраций и опубликованных заявок. Запросы ограничены
параметрами `FIPS_PUBLIC_MAX_RESULTS`, `FIPS_PUBLIC_PAGE_SIZE` и
`FIPS_PUBLIC_MIN_INTERVAL`; временные ошибки повторяются с задержкой.

Нормализованная карточка содержит `record_id`, `source`, `external_id`, текст
и вид обозначения, владельца, классы, статус, даты, номера заявки и
регистрации, а также ссылку на изображение, если она присутствует в ответе.

## Участие в полном анализе и передача в LLM

Публичный провайдер используется не только ручным endpoint поиска. При запуске
полного анализа `run_full_analysis` вызывает `run_conflict_search`, который:

1. загружает классы МКТУ, ранее определённые в деле; подтверждённые классы
   имеют приоритет над предложенными;
2. первым проходом ищет регистрации и заявки строго в этих классах по
   исходному, транслитерированному и переводному вариантам обозначения;
3. только после class-first прохода выполняет узкий контрольный поиск по всему
   реестру — для известных знаков и однородных товаров из разных классов;
4. дедуплицирует результаты и рассчитывает сходство правилами;
5. до числового отсечения передаёт в LLM максимум 10 карточек, ставя выше
   записи из выбранных классов и с действующим/ожидающим статусом;
6. сохраняет карточку как риск, если она прошла детерминированный порог либо
   LLM обоснованно поднял её на ручную проверку при наличии независимых
   признаков. Числовые коэффициенты при этом не переписываются.

В LLM передаются только необходимые для относительных оснований сведения:

- заявляемое обозначение, его вид, описание, транслитерация, перевод,
  приоритет, выбранные классы и признак их подтверждения;
- `source` — регистрация либо опубликованная заявка;
- текст обозначения, владелец, классы и статус;
- даты и номера заявки/регистрации;
- рассчитанные системой фонетический, графический, смысловой и товарный
  коэффициенты и общий показатель.

Промпт: `backend/prompts/legal/registry_conflict_review.yaml`. Код подготовки
и фильтрации контекста: `backend/app/agents/legal/registry_context.py`.

LLM не является источником реестровых фактов и не пересчитывает коэффициенты.
Она применяет последовательность опытного поверенного: статус и приоритет,
объём товаров/услуг, общее впечатление, сильные и слабые элементы, звуковое,
графическое и смысловое сходство, взаимное влияние сходства и однородности,
аргументы, контраргументы и недостающие доказательства. Методика основана на
пунктах 40–45 Правил № 482 и пункте 162 Постановления Пленума ВС РФ № 10.
Модель формирует пояснение факторов смешения и рекомендацию для ручной проверки.
Ответ связывается только с `record_id`, реально присутствовавшими во входе;
придуманные моделью идентификаторы отбрасываются. Ошибка LLM не отменяет поиск
и детерминированную оценку.

В `RiskAssessment.verification_json` сохраняются:

```json
{
  "method": "deterministic_similarity + llm_semantic + llm_registry_review",
  "records_examined": 42,
  "conflicts_found": 7,
  "semantic_checks": 2,
  "class_first_search": true,
  "selected_class_records": 31,
  "broader_control_records": 11,
  "llm_registry_records_sent": 10,
  "llm_elevated_record_ids": ["rospatent-public:registration:..."],
  "llm_registry_review": {
    "summary": "...",
    "record_reviews": [
      {
        "record_id": "rospatent-public:application:...",
        "legal_risk": "high",
        "requires_attention": true,
        "comment": "...",
        "mark_similarity_analysis": "...",
        "goods_homogeneity_analysis": "...",
        "priority_and_status_analysis": "...",
        "confusion_factors": ["..."],
        "counterarguments": ["..."],
        "missing_evidence": ["..."],
        "recommended_action": "..."
      }
    ]
  }
}
```

Если значимых карточек не осталось, система не выставляет успокаивающий уровень
`low`. Результат помечается как `inconclusive`: «в доступной выдаче значимые
совпадения не выявлены» не равнозначно утверждению «рисков нет».

Режим источника и ограничение полноты также попадают в итоговый отчёт.

## Какой API используется

Для чтения сведений о зарегистрированных товарных знаках и опубликованных
заявках используется API ИС «Поисковая платформа»:

- базовый URL: `https://searchplatform.rospatent.gov.ru/patsearch/v0.2/`;
- `GET /datasets` — доступные ключу наборы данных;
- `POST /search` — поиск по наборам;
- `GET /docs/{id}` — полная карточка найденного документа;
- авторизация: `Authorization: Bearer <API key>`.

Официальная точка входа в документацию:
<https://online.rospatent.gov.ru/open-data/open-api>.

API `/external_api` системы «Онлайн Роспатент» предназначен для работы
пользователя со своими обращениями и подачей заявлений. Он не подменяет поиск
по публичному реестру, поэтому в этой интеграции не используется.

## Настройка приложения

Ключ выпускается зарегистрированным пользователем в разделе генерации ключей
ИС «Поисковая платформа». Ключ нельзя добавлять в Git. Укажите его только в
`backend/.env`:

```dotenv
FIPS_PROVIDER=fips
FIPS_BASE_URL=https://searchplatform.rospatent.gov.ru/patsearch/v0.2/
FIPS_API_KEY=<ваш ключ>
FIPS_TRADEMARK_DATASETS=
FIPS_APPLICATION_DATASETS=
FIPS_CLASS_FILTER_FIELD=classification.icgs
FIPS_TIMEOUT=30
FIPS_VERIFY_SSL=true
```

При пустых `FIPS_TRADEMARK_DATASETS` и `FIPS_APPLICATION_DATASETS` приложение
получает список через `/datasets` и пытается распознать наборы по названиям.
Если названия наборов для выданного ключа отличаются, вызовите локальный
`GET /api/v1/registry/datasets` и задайте нужные идентификаторы через запятую.

После изменения `.env` перезапустите backend.

## Локальные методы приложения

- `POST /api/v1/registry/search` — поиск регистраций, заявок или обоих типов;
- `GET /api/v1/registry/datasets` — доступные ключу наборы;
- `GET /api/v1/registry/records/{record_id}` — карточка документа.

Пример запроса после авторизации в приложении:

```json
{
  "query": "Регистр",
  "classes": [42],
  "search_type": "fuzzy",
  "source": "both",
  "max_results": 50
}
```

Основной сценарий анализа проекта также использует этот провайдер: поиск
выполняется по регистрациям и опубликованным заявкам, результаты приводятся к
единой внутренней карточке, участвуют в оценке сходства и после отбора
передаются в структурированный LLM-review.

## Ограничения

- Интеграция с Поисковой платформой только читает данные.
- Реальная подача заявления намеренно остаётся отдельным выключенным действием.
- Отсутствие результатов поиска не является юридической гарантией возможности
  регистрации; заключение всё равно требует проверки специалистом.
