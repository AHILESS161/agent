# Тестирование

**Актуализировано:** 15 августа 2026 года. Pytest собирает **704 backend-теста**;
успешность всей выборки подтверждается только полным запуском, а не сбором.

## Команды

```bash
cd backend
../venv/Scripts/python -m pytest                      # всё
../venv/Scripts/python -m pytest -m unit              # только модульные
../venv/Scripts/python -m pytest -m api               # только API
../venv/Scripts/python -m pytest -m e2e               # только сквозные
../venv/Scripts/python -m pytest --cov=app            # с покрытием
```

Frontend:

```bash
cd frontend
npm run check      # tsc --noEmit
npm run build      # сборка
```

**Текущий состав: 704 backend-теста собираются.** Последняя целевая регрессия
маршрутизации клиентских заявок, назначения юриста и пошлин: 41 тест прошёл.

Фикстура `tests/fixtures/egrul_sample.py` — обезличенная выписка,
воспроизводящая **все шесть ловушек** настоящей: ОГРН вразрядку, номера
ГРН той же длины, ИНН руководителя и учредителей, одинаковые подписи
ФИО в разных разделах, «Дата регистрации» трижды, колонтитул посреди
таблицы.

Реквизиты синтетические, но контрольные суммы корректные — иначе тесты
валидации не имели бы смысла. Данные из приложенных документов в тесты
не копируются.

## Тесты, которые нашли настоящие ошибки

Не написаны «под зелёный прогон» — каждый выявил дефект:

1. **CP1251 пропускал бинарные данные как `.txt`** — однобайтовая
   кодировка декодирует почти любые байты. Добавлена проверка на
   управляющие символы.
2. **Повреждённый PDF с валидной сигнатурой ронял запрос в 500** —
   `pdfminer` бросал исключение мимо обработчика. Стал штатным отказом
   с сохранением оригинала.
3. **Паттерн маскирования паспорта съедал 10-значный ИНН юрлица** —
   4+6 цифр подряд. Потребован явный разделитель.
4. **Решение специалиста перезатиралось пересчётом** — подтверждённое
   поле снова показывалось как конфликт, потому что значение в карточке
   дела по-прежнему отличалось от выписки. Работа человека терялась при
   каждом обновлении экрана. Найдено **только проверкой в браузере**.
5. **Коллизия маршрутов** — `/{id}/documents` уже был занят пакетами
   сгенерированных документов.

## Что проверено вручную

На реальных приложенных документах, через живой сервер и браузер:

- загрузка выписки ЕГРЮЛ → 10 страниц → тип `egrul_extract` (0.95);
- скачивание побайтно идентично оригиналу (сверка SHA-256);
- извлечение 21 поля, `llm_used: false`;
- сверка полей: конфликты между выпиской и карточкой дела;
- подтверждение поля → список блокирующих сократился;
- повторное извлечение сохранило подтверждённые поля;
- 401 без токена на всех защищённых эндпоинтах.

## Известные пробелы

- **Нет E2E-теста полного happy path** через API одним прогоном —
  сценарий проверен вручную, но не автоматизирован.
- RAG покрыт unit-тестами retrieval, цитирования и анализатора, но не хватает
  полного юридического eval-набора на противоречивые и устаревшие источники.
- Провайдеры `mock`, официальный bearer API и публичный read-only адаптер
  покрыты отдельными тестами; живой внешний сервис не входит в CI.
- **Нет frontend-тестов** (ни модульных, ни браузерных).
- Тесты `mvp-run` не покрывают поведение при недоступном LLM.
- Клиентский переход «создание → видимость администратору → назначение юриста»
  и доступ обеих профессиональных ролей к пошлинам покрыты API-тестом
  `test_client_admin_flow.py`.

Все пункты вынесены в `docs/roadmap.md`.

## Соглашения

- Тесты и комментарии на русском — как и остальной новый код.
- Фикстуры обезличены.
- Rate limiting в тестах отключается фикстурой `disable_rate_limit`;
  сам лимитер покрыт отдельно.
- Пользователи создаются через `api_user_factory` напрямую в БД:
  регистрация через API закрыта для всех, кроме администратора.
