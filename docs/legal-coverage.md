# Полнота правовой проверки

> **Актуализировано 26.08.2026:** результаты реестрового поиска участвуют в
> правовом анализе, классы МКТУ имеют приоритет при поиске, а интерфейс отделяет
> реальные риски от успешно пройденных проверок. Анализ остаётся предварительным.

Сверка того, что делает система, с проверками, которые патентный
поверенный проводит перед подачей заявки на товарный знак.

Документ честный: он показывает не только покрытое, но и пробелы.

## Исправленный дефект базы знаний

Ранее в `knowledge/gk_rf_part4_trademarks.md` была неверно изложена нумерация
пунктов статьи 1483 ГК РФ. Ошибочный пересказ удалён, а основания вынесены в
отдельный источник `gk_rf_st1483_refusal_grounds.md`. В исходном файле оставлена
явная запись об исправлении, чтобы старая формулировка не вернулась незаметно.

Остаётся принципиальное ограничение: проверка цитат защищает от выдуманной
моделью нормы, но не от ошибки внутри самого корпуса. Поэтому юридические
источники и их редакции всё равно требуют периодической проверки юристом.

### A. Заявитель и его правоспособность

| Проверка | Состояние |

### D. Оценка сходства

| Вид | Состояние |
|---|---|
| Фонетическое | ⚠️ детерминированная оценка, требует юридической калибровки |
| Семантическое | ⚠️ детерминированный слой и опциональная LLM-проверка неоднозначных пар |

## Сводка

| Раздел | Покрытие |
|---|---|
| A. Заявитель | ~50 % |
| B. Абсолютные основания | частично: основные категории, без ряда специальных исключений |
| C. Относительные основания | частично: п. 6, остальные чужие права почти не покрыты |
| D. Оценка сходства | частично: текстовые коэффициенты и LLM-review, без полноценного CV |
| E. МКТУ | ~70 %: полный актуальный справочник и подтверждение класса; нет проверки чрезмерно общих формулировок |
| F. Поиск | частично: регистрации и заявки, полнота зависит от провайдера |
| G. Приоритет | 0 % |
| H. Формальные требования | ~30 % |
| I. Стратегия | ~10 % |

**Вывод.** Система закрывает начало процесса — приём документа,
извлечение и подтверждение реквизитов заявителя — и имеет рабочий
контур проверяемого правового анализа. Но как инструмент полной
предрегистрационной проверки она пока покрывает меньшую часть работы
поверенного.

Наиболее заметные пробелы, влияющие на практическую ценность:

1. **Относительные основания** — п. 7, 8, 9 не покрыты вовсе, хотя
   именно конфликты с чужими правами дают большинство отказов.
2. **Однородность товаров** — без неё оценка конфликта неполна.
3. **Приобретённая различительная способность и дискламация** —
   основные практические инструменты преодоления отказа.
4. **Проверка по фирменным наименованиям** — данные ЕГРЮЛ уже
   извлекаются, источник для проверки частично доступен.
5. **Приоритет** — сроки не контролируются.
6. **Пошлины** — не рассчитываются.

## Что нужно от владельца продукта

1. **Юридическая проверка корпуса базы знаний.** Нумерация пунктов
   ст. 1483 сейчас неверна; остальной корпус не проверялся юристом.
2. **Источники данных** для поиска: реестр ТЗ, заявки, общеизвестные
   знаки, НМПТ, Мадридские регистрации.
3. **Автоматическая проверка формулировок МКТУ** на чрезмерную общность и
   допустимость для официального перечня (сам актуальный справочник уже подключён).
4. **Методика оценки однородности** товаров и услуг, принятая в фирме.
5. **Приоритеты**: какие из пробелов закрывать первыми.
