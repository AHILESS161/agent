## 1. Что было найдено в исходном состоянии

### Блокирующие проблемы

**Приложение не запускалось вообще.**

```
app/api/v1/endpoints/intake.py:20
    from app.api.dependencies import _get_llm_provider, _get_prompt_registry
ImportError: cannot import name '_get_llm_provider' from 'app.api.dependencies'
```

`app/api/dependencies/` был пустым каталогом без `__init__.py`. Падал
`router.py` → `main.py` → uvicorn. **Весь pytest-сьют не собирался: 0 тестов.**

**Frontend не имел слоя данных.**

- `client/src/lib/queryClient.ts` → `API_BASE = "."` (same-origin)
- `server/routes.ts` → `registerRoutes()` не регистрировал **ни одного маршрута**
- все 10 страниц импортировали `lib/mock-data.ts` (425 строк)
- `apiRequest`/`getQueryFn` были определены и **не использовались нигде**
- `lib/auth.tsx:18` → `login(email, _password)` — **пароль игнорировался**,
  подходил любой; сессия жила только в памяти React

**`pdfplumber` не установлен и отсутствовал в `requirements.txt`**, хотя
`document_text_extractor.py` — единственный путь чтения PDF — импортировал
его в `try/except`. Разбор PDF молча не работал.

**Миграций не было.** Каталог `migrations/` пуст, alembic в зависимостях
не использовался, `session.py` создавал схему через `create_all()` при старте.

**Отсутствовали все сущности документов**: `SourceDocument`, `DocumentPage`,
`ExtractedField`, `FieldCandidate`, `FieldConfirmation`. Загруженный файл
парсился и **выбрасывался**.

### Уязвимости

| Проблема | Последствие |
|---|---|
| `POST /auth/register` открыт и принимал поле `role` | любой мог создать себе учётную запись **администратора** |
| `/api/v1/intake/*` без авторизации | публичная загрузка файлов до 25 МБ |
| Тип файла проверялся по расширению | переименованный файл проходил проверку |
| `_step_submission` внутри общего прогона `mvp-run` | подача заявки выполнялась **автоматически**, без подтверждения |
| `ProviderFactory.create("fips")` молча возвращал mock | demo-поиск выдавался за полноценный поиск по реестру |
| Нет rate limiting | подбор пароля, исчерпание диска |
| ПДн в логах не маскировались | выписки содержат ФИО, ИНН, паспортные данные |

### Расхождения

- **Роли**: backend `admin/lawyer/manager/client`, frontend `admin/lawyer/client`.
- **Статусы дел**: словари пересекались **только по двум значениям** из 18
  (`draft`, `submitted`) — в таблице заявок статусы отображались пустыми.
- **Формат полей**: backend `full_name`, frontend `fullName` — `TopBar`
  падал в белый экран сразу после входа.

### Что было сделано добротно

| Компонент | Оценка |
|---|---|
| `agents/intake/application_pdf_parser.py` (921 стр.) | реальный парсер по INID-кодам ВОИС ST.9 |
| `infrastructure/rag/pipeline.py` (429 стр.) | честный BM25 на чистом Python, интерфейс под замену на Qdrant |
| `providers/mock_fips.py` (906 стр.) | 55 записей демо-реестра, фонетика, fuzzy; честно назван mock |
| `services/completeness_engine.py`, `state_machine.py` | реальные правила и 18 состояний |
| `models.py` | 22 типизированные таблицы, аудит-лог |

### Документация вводила в заблуждение

`docs/` (10 файлов, ~245 КБ) датированы **раньше** кода — это проектные
спецификации, написанные наперёд, а не описание существующего.

README в разделе «Статус модулей» отмечал ✅ «Реализован» почти всё,
включая «Frontend (React) ✅ Реализован» — при нулевой интеграции с backend
и неработающем приложении.

## 3. Текущее состояние

### Работает на реальных данных

- вход по JWT, сессия переживает перезагрузку, 401 возвращает ко входу;
- список дел и карточка дела;
- загрузка документа с проверкой по сигнатуре, хранение, скачивание;
- постраничное извлечение текста;
- определение типа документа правилами;
- извлечение реквизитов ЕГРЮЛ (regex, без LLM);
- сверка `реестр → дело → заявление` с источниками и страницами;
- подтверждение полей специалистом с историей решений;
- аудит действий, маскирование ПДн.

### Работает в demo-режиме (помечено в интерфейсе)

- поиск по реестру товарных знаков — 55 записей демо-датасета;
- LLM-агенты (классификация МКТУ, правовой анализ, рекомендации);
- RAG на BM25 поверх трёх файлов базы знаний.

### Не подключено к БД (помечено баннером в интерфейсе)

Вкладки: полнота данных, правовой анализ, классы МКТУ, конфликты,
рекомендации, документы, история. Страницы: дашборд, клиенты, аудит,
администрирование, уведомления.

### Не реализовано

- OCR для сканов;
- inbound router (CRM, email, webhook) и идемпотентность;
- фоновые задачи — `mvp-run` выполняется синхронно в HTTP-запросе;
- генерация отчёта о рисках как артефакта и экспорт в PDF/DOCX;
- реальная интеграция с ФИПС/Роспатентом;
- персистентность RAG-индекса (сейчас в памяти процесса).

## 4. Критические риски

| Риск | Статус |
|---|---|
| Автоматическая подача заявки | закрыт: два флага + подтверждение |
| Самоназначение роли admin | закрыт: регистрация только для admin |
| Demo-данные принимаются за реальные | закрыт: баннеры в UI, явная ошибка вместо подмены провайдера |
| ПДн в логах | закрыт: маскирование |
| Чекбоксы бланка угадываются | закрыт: всегда ручное подтверждение |
| `mvp-run` синхронный | **открыт**: при медленном LLM запрос может отвалиться по таймауту |
| RAG-индекс в памяти | **открыт**: теряется при перезапуске |
| Один процесс для rate limit | **открыт**: при нескольких воркерах счётчик нужно вынести в Redis |
