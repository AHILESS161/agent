# Roadmap и честный список ограничений

---

## Критерий готовности MVP и текущее соответствие

> Внешний тестировщик может по защищённой временной ссылке войти
> в систему, создать дело или получить его через тестовый inbound
> endpoint, загрузить приложенную справку, увидеть реквизиты,
> извлечённые главным образом regex-правилами, подтвердить поля,
> увидеть сопоставление с полями заявления, получить предварительный
> отчёт о рисках с источниками и ограничениями, увидеть результаты
> demo-поиска, сформировать и скачать черновой пакет документов.

| Шаг | Состояние |
|---|---|
| Вход по временной ссылке | ✅ JWT, туннель описан в `demo-deployment.md` |
| Создать дело | ✅ через интерфейс |
| Получить дело через inbound endpoint | ❌ inbound router не реализован |
| Загрузить справку | ✅ с проверкой по сигнатуре |
| Увидеть реквизиты из regex | ✅ 21 из 21 поля, `llm_used: false` |
| Подтвердить поля | ✅ принять/изменить/отклонить/оставить пустым + история |
| Сопоставление с полями заявления | ✅ с источником, страницей и паттерном |
| Отчёт о рисках с источниками | ⚠️ анализ есть в demo-режиме, отчёт как артефакт — нет |
| Результаты demo-поиска | ⚠️ работает, но экран не подключён к БД |
| Сформировать и скачать пакет | ❌ генератор есть, сквозной сценарий не собран |

**Вывод: MVP не готов.** Основной контур «документ → реквизиты →
подтверждение → сопоставление» работает на реальных данных. Не хватает
трёх последних шагов: отчёт, генерация пакета, экспорт.

## P1 — до готовности MVP

1. **Генерация черновика заявления** из подтверждённых полей.
   Не заполнять поля со статусом `unconfirmed`/`conflict`/`needs_review`
   (правило уже реализовано в `can_generate_draft`). Preview перед
   экспортом, версионирование, статусы `draft` → `ready_for_review` →
   `approved_by_specialist` → `exported`.

2. **Отчёт о рисках как артефакт**: сведения о деле и заявителе, статусы
   подтверждения, абсолютные и относительные основания, источники,
   ограничения, режим поиска (real/demo/limited), версия модели, версия
   базы знаний, идентификатор прогона. Экспорт в PDF и DOCX/HTML.

3. **Фоновые задачи.** `POST /{id}/mvp-run` выполняет 7 шагов синхронно
   в HTTP-запросе — при медленном LLM запрос отвалится по таймауту.
   Таблица `BackgroundJob` уже есть, нужен исполнитель.

4. **Подключение оставшихся вкладок к БД**: полнота данных, правовой
   анализ, классы МКТУ, конфликты, рекомендации, документы, история.
   Сейчас помечены баннером «демонстрационные данные».

5. **Inbound router**: `InboundEvent` с `idempotency_key`, адаптеры
   `CRMAdapter`/`EmailAdapter`, тестовый webhook с проверкой подписи,
   сохранение исходного payload, привязка к делу или создание черновика.

6. **Персистентность RAG.** Индекс живёт в памяти процесса и теряется
   при перезапуске. Таблицы `KnowledgeSource`/`KnowledgeChunk` есть,
   нужна запись и версионирование источников.

7. **Переработка парсера бланка заявки.** На приложенном образце
   `application_pdf_parser.py` подставляет подпись поля вместо значения
   обозначения, ошибается в виде знака, кладёт личный ИНН плательщика
   в «номер международной регистрации», а `confidence` — зашитые
   константы. Подробности: `docs/document-extraction.md`, §6.

8. **Тесты**: E2E happy path одним прогоном, RAG (нет источника,
   неполный контекст, невалидный JSON, запрет галлюцинаций), демо-провайдер
   ФИПС, frontend.

## P2 — после MVP

- Улучшение OCR сложных сканов: поворот, таблицы и рукописный текст. Базовое
  распознавание PDF/PNG/JPG через Tesseract уже работает.
  Требует tesseract (+~300 МБ в образе) и хранения confidence по каждому
  фрагменту.
- **PostgreSQL** вместо SQLite (в `docker-compose.yml` закомментирован).
- **Qdrant / pgvector** вместо BM25.
- **Реальная интеграция с ФИПС/Роспатентом** — при наличии легального
  доступа. Сейчас `ProviderFactory.create("fips")` намеренно поднимает
  ошибку вместо подмены демо-данными.
- **Rate limit в Redis** — текущий счётчик в памяти корректен только
  для одного процесса.
- **Роли `viewer`** отдельно от `client`, если понадобится различать.
- **Сокращение JS-бандла** (556 КБ; предупреждение сборщика).
- Модуль `submission` для реальной подачи — только за feature flag.

## Честные ограничения текущей версии

**Про извлечение**

- OCR работает для сканированных PDF и изображений; результат помечается и
  требует проверки специалистом.
- Отмеченность чекбоксов бланка из PDF определить невозможно (они
  векторные, в текстовом слое отсутствуют). Вид знака, тип приоритета
  и пункт пошлины заполняются только вручную.
- Паттерны написаны и проверены на **одной** типовой форме выписки ЕГРЮЛ.
  Другие форматы (ЕГРИП, старые формы, выписки из иных источников)
  потребуют своих наборов паттернов.
- Извлечение из ЕГРИП объявлено в классификаторе, но паттернов для него
  нет — документ будет распознан по типу и не обработан.

**Про AI**

- Поиск по реестру товарных знаков работает на демо-датасете из 55 записей.
  Это **не** полный поиск по Роспатенту, и так и написано в интерфейсе.
- RAG построен на BM25 поверх трёх файлов базы знаний. Это работающий,
  но небольшой корпус.
- Правовой анализ носит предварительный характер и не является
  юридическим заключением.

**Про эксплуатацию**

- SQLite. Для одновременной работы нескольких пользователей нужен PostgreSQL.
- Фоновых задач нет; долгие операции выполняются в HTTP-запросе.
- Rate limit корректен только при одном процессе.
- RAG-индекс теряется при перезапуске.

**Про интерфейс**

- Семь вкладок карточки дела и пять страниц читают демонстрационные
  данные. Каждая помечена баннером.
- Frontend-тестов нет.
- Роль `manager` в интерфейсе не разделена (по согласованию — двух
  ролей достаточно для демо).

## Что требует решения владельца продукта

1. **Легальный доступ к данным Роспатента/ФИПС** — без него поиск
   останется демонстрационным.
2. **Корпус базы знаний** для RAG: какие нормативные и методические
   материалы допустимо использовать как основание выводов.
3. **Политика хранения ПДн**: сроки, удаление, доступ. Система обрабатывает
   выписки с ФИО, ИНН и паспортными данными.
4. **Форматы экспорта** пакета документов и требования к шаблонам.
5. **Нужны ли остальные типы реестровых выписок** (ЕГРИП и прочие) в MVP.
