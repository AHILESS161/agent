# Оценка извлечения ЕГРЮЛ и ЕГРИП

## Зачем нужен отдельный eval-набор

Успешный разбор одной выписки не доказывает качество контура. Формат ФНС,
порядок строк, текстовый слой PDF и качество скана отличаются. Поэтому качество
измеряется по заранее размеченным документам, а не по субъективной уверенности
алгоритма.

## Что уже автоматизировано

`registry_evaluation.evaluate_registry_extraction` сравнивает результат с
эталоном по каждому полю и возвращает:

- долю точно извлечённых полей;
- долю точно извлечённых обязательных полей;
- пропуски и ошибочные значения;
- перечень полей, которые нужно сверить вручную;
- итог `safe_to_prefill`, запрещающий тихое автозаполнение при пропуске,
  конфликте, ошибке валидации или низкой уверенности.

Начальный обезличенный набор включает структурно реалистичные ЕГРЮЛ и ЕГРИП,
ловушки с ГРН/ОГРН, чужими ИНН, повторяющимися датами и искусственно
повреждённый OCR-текст. На чистых фикстурах обязательные поля совпадают на
100%; повреждённый текст намеренно переводится в ручную проверку.

## Что требуется до внешнего пилота

Синтетические фикстуры не заменяют реальные документы. Нужен закрытый,
обезличенный корпус минимум из следующих групп:

1. ЕГРЮЛ старого и нового макета с текстовым слоем;
2. ЕГРИП старого и нового макета с текстовым слоем;
3. сканы 150, 200 и 300 dpi;
4. поворот, перекос, шум, бледная печать и разрыв строк;
5. длинные наименования и адреса, отсутствие отчества, несколько руководителей;
6. документы с конфликтующими или невалидными идентификаторами.

Для каждого документа хранится только обезличенный исходник и JSON-эталон.
Нельзя добавлять в Git паспортные данные и реальные непубличные сведения.

## Критерий выпуска

- обязательные идентификаторы на PDF с текстовым слоем: не менее 99% exact
  match;
- на поддерживаемых сканах: не менее 95% exact match;
- опасная ошибка, при которой неверное значение признано безопасным для
  автозаполнения: 0%;
- любой пропуск, конфликт или невалидная контрольная сумма приводит к понятной
  ручной проверке конкретного поля.
