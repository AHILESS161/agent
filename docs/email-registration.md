# Регистрация клиентов по почте — KAN-48 / KAN-49

Открытая регистрация создаёт только роль `client`. Доступ к старому
`POST /auth/register`, который создаёт сотрудников, остаётся у администратора.
Публичные схемы отклоняют дополнительные поля, включая `role` и `is_active`.

Клиент вводит почту, получает ссылку на один час, затем задаёт имя и пароль.
До этого аккаунта нет: нельзя войти или запустить анализ. Подтверждение создаёт
пользователя и атомарно погашает все ссылки этого адреса. Пароль задаётся только
владельцем ссылки; запрос письма не может заранее назначить чужому адресу пароль.
В БД хранятся только SHA-256 токенов. Токен в URL расположен после `#`, поэтому
не попадает в HTTP access-log и Referer. После успешного подтверждения URL очищается.

Существующие аккаунты, их роли и пароли не изменяются. Ответ на запрос письма
одинаков для занятого и нового адреса; ошибка доставки возвращает 503, а не
ложное сообщение об успехе. Лимиты отправки фиксируются в PostgreSQL до SMTP:
5 писем на адрес в сутки, 10 запросов на IP в час, 100 на систему в сутки.
Просроченные запросы и старые счётчики очищаются при новых запросах.

## Настройка отправки

В защищённом `.env.production` заполнить `SMTP_HOST`, `SMTP_PORT`,
`SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` и `PUBLIC_APP_URL`.
Для порта 465 используется `SMTP_USE_SSL=true`; для STARTTLS (обычно 587) —
`false`. Незашифрованный SMTP не поддерживается, сертификат проверяется.
Почтовый провайдер и подтверждённый адрес отправителя выбираются владельцем.
Секреты не публикуются в Git/Jira. Доставку проверяют на разрешённом тестовом адресе.

После настройки установить `PUBLIC_SIGNUP_ENABLED=true` и пересоздать API.
При отсутствии настройки `/api/v1/auth/signup/config` возвращает `enabled: false`,
форма объясняет временную недоступность. Настройка не активирует демо-аккаунты.

## Проверки

API-регрессии покрывают создание клиента, запрет входа до подтверждения,
подмену роли, истечение и повторное использование токена, повторную отправку,
существующего администратора, ошибку SMTP и сохранение квоты при ошибке.
CI отдельно проверяет две одновременные ссылки для одного адреса на PostgreSQL.
Реальная доставка и приёмка пользовательского пути — задача KAN-49 на Дарье.
