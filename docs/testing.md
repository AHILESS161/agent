# Тестирование

**Актуализировано:** 1 сентября 2026 года. Последний полный локальный прогон содержит
**825 backend-тестов** и завершён успешно.

## Команды

```bash
cd backend
python -m pytest                      # всё; если окружение уже активировано
python -m pytest -m unit              # только модульные
python -m pytest -m api               # только API
python -m pytest -m e2e               # только сквозные
python -m pytest --cov=app            # с покрытием
```

В локальном Windows-репозитории без активации окружения используйте
`../venv/Scripts/python.exe`; в Linux/macOS — `../venv/bin/python`.

Frontend:

```bash
cd frontend
npm run check      # tsc --noEmit
npm run build      # сборка
```

**Текущий подтверждённый состав: 825 backend-тестов проходят.** Для тестов,
создающих временные файлы в ограниченной среде, задавайте `--basetemp` внутри
рабочего каталога.

После изменений 29 августа дополнительно выполнен целевой прогон **135
уникальных backend-тестов** по подбору МКТУ, официальному DOCX, комплекту
подачи, правовому анализу и fallback моделей. Также успешно выполнены
`npm run check` и production-сборка frontend. Полный счётчик всего набора будет
обновлён после очередного полного прогона, поэтому цифра 825 выше остаётся
последним подтверждённым полным baseline, а не предполагаемой суммой тестов.

`test_registry_evaluation.py` проверяет не только отдельные regex, но и
измеримый результат всего документа: exact match по полям и обязательный
ручной fallback при повреждённом OCR или конфликтующих значениях.

Сценарий повторно используемых реквизитов заявителя проверяется API-тестом
`test_client_can_save_reusable_applicant_profile`: профиль сохраняется через
`PATCH /auth/me` и возвращается последующим `GET /auth/me`. На frontend к этому
сценарию ведут флажок при создании заявки и кнопка на экране сверки данных.

`test_client_progress.py` закрепляет прогресс карточки клиента по фактическим
артефактам дела: новый черновик показывает первый этап, добавленный класс МКТУ —
второй, а созданное задание полного анализа — третий, даже если общий статус
заявки всё ещё равен `draft`.

## Тесты, которые нашли настоящие ошибки

Не написаны «под зелёный прогон» — каждый выявил дефект:

1. **CP1251 пропускал бинарные данные как `.txt`** — однобайтовая
   кодировка декодирует почти любые байты. Добавлена проверка на
   управляющие символы.
2. **Повреждённый PDF с валидной сигнатурой ронял запрос в 500** —
   `pdfminer` бросал исключение мимо обработчика. Стал штатным отказом
   с сохранением оригинала.
3. **Паттерн маскирования паспорта съедал 10-значный ИНН юрлица** —
   4+6 цифр подряд. Потребован явный разделитель.
4. **Решение специалиста перезатиралось пересчётом** — подтверждённое
   поле снова показывалось как конфликт, потому что значение в карточке
   дела по-прежнему отличалось от выписки. Работа человека терялась при
   каждом обновлении экрана. Найдено **только проверкой в браузере**.
5. **Коллизия маршрутов** — `/{id}/documents` уже был занят пакетами
   сгенерированных документов.

## Что проверено вручную

На реальных приложенных документах, через живой сервер и браузер:

- загрузка выписки ЕГРЮЛ → 10 страниц → тип `egrul_extract` (0.95);
- скачивание побайтно идентично оригиналу (сверка SHA-256);
- извлечение 21 поля, `llm_used: false`;
- сверка полей: конфликты между выпиской и карточкой дела;
- подтверждение поля → список блокирующих сократился;
- повторное извлечение сохранило подтверждённые поля;
- 401 без токена на всех защищённых эндпоинтах.
- структура внешнего DOCX-референса «Юная модница»: изображение находится в
  области (540), описание — в (571), отмечены цветное исполнение и
  комбинированный вид; незаполненные поля не принимались за готовые данные;
- генератор юридических образцов создаёт шесть обезличенных DOCX для матрицы
  «юрлицо/ИП/физлицо × словесный/комбинированный знак».

## Известные пробелы

- **Нет E2E-теста полного happy path** через API одним прогоном —
  сценарий проверен вручную, но не автоматизирован.
- RAG покрыт unit-тестами retrieval, цитирования и анализатора, но не хватает
  полного юридического eval-набора на противоречивые и устаревшие источники.
- Провайдеры `mock`, официальный bearer API и публичный read-only адаптер
  покрыты отдельными тестами; живой внешний сервис не входит в CI.
- **Нет frontend-тестов** (ни модульных, ни браузерных).
- Тесты `mvp-run` не покрывают поведение при недоступном LLM.
- Клиентский переход «создание → видимость администратору → назначение юриста»
  и доступ обеих профессиональных ролей к пошлинам покрыты API-тестом
  `test_client_admin_flow.py`.

Все незавершённые проверки ведутся в [`backlog.md`](backlog.md), а крупные этапы
качества — в [`roadmap.md`](roadmap.md).

## Соглашения

- Тесты и комментарии на русском — как и остальной новый код.
- Фикстуры обезличены.
- Rate limiting в тестах отключается фикстурой `disable_rate_limit`;
