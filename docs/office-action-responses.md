# Ответы на уведомления Роспатента

**Состояние:** реализован клиентский черновик с обязательной проверкой человеком.

## Пользовательский путь

В карточке дела есть раздел «Ответ Роспатенту». Пользователь:

1. загружает уведомление в PDF, DOCX, TXT, PNG или JPEG;
2. при наличии указывает срок ответа;
3. отмечает применимые обстоятельства об однородности товаров и услуг;
4. отдельно добавляет доказательства приобретённой различительной способности;
5. описывает каждый отмеченный факт и прикладывает подтверждающие файлы;
6. сохраняет сведения и запускает подготовку черновика;
7. читает краткое объяснение требования, видит недостающие материалы и скачивает DOCX.

В профессиональной карточке тот же объект доступен во вкладке «Ответ». Юрист
видит сохранённые клиентом факты и приложения, может уточнить их, добавить
материалы, повторно сформировать черновик и скачать его для правовой проверки.

Одна заявка может иметь несколько последовательных уведомлений и ответов. В
интерфейсе открывается последний созданный проект; предыдущие хранятся в БД и
доступны через API.

## Однородность товаров и услуг

Собираются самостоятельные факты о назначении, природе, материале, покупателях,
каналах реализации, взаимозаменяемости, совместном использовании и обычном
происхождении от одного производителя. В подсказках и промпте прямо закреплено:
совпадение класса МКТУ само по себе не доказывает однородность, а разные классы
не гарантируют её отсутствие.

## Приобретённая различительная способность

Можно добавить дату начала использования, территорию и объём продаж, выручку,
расходы на рекламу, публикации, договоры и каталоги, статистику сайта и
маркетплейсов, опросы, фотографии товара и упаковки.

Галочка означает не наличие документа вообще, а подтверждение конкретного
утверждения клиентом. Поэтому отмеченный пункт без текста API отклоняет. Каждый
файл связывается с конкретным критерием, а не с ответом абстрактно.

## Границы LLM

В модель передаются текст уведомления, основные данные заявки и только пункты,
у которых одновременно `confirmed=true` и заполнено поле `fact`. Названия
приложений передаются для формирования перечня приложений. Модели запрещено:

- придумывать факты, даты, суммы, документы и правовые нормы;
- считать, что название файла доказывает его содержание;
- представлять отсутствие данных как установленное обстоятельство;
- подменять анализ однородности простым сравнением номеров МКТУ.

После контрольного прогона GigaChat фактическая часть дополнительно защищена от
«дрейфа» модели: полный текст письма собирается детерминированно из дословно
подтверждённых полей. LLM предлагает только список материалов, которых может не
хватать. Фрагмент уведомления показывается без свободного пересказа моделью.
При ошибке LLM факты и файлы остаются сохранёнными, а пользователь получает
предложение повторить генерацию. DOCX всегда помечается как автоматически
сформированный черновик, требующий проверки перед отправкой.

Тестовые материалы:

- [`samples/demo-rospatent-notice.txt`](samples/demo-rospatent-notice.txt) —

- [`samples/demo-rospatent-response-preview.md`](samples/demo-rospatent-response-preview.md) —

## API

- `GET /api/v1/applications/{id}/office-actions` — история проектов;
- `POST /api/v1/applications/{id}/office-actions` — новый проект;
- `PUT /api/v1/applications/{id}/office-actions/{response_id}` — сохранить факты;
- `POST /api/v1/applications/{id}/office-actions/{response_id}/generate` — создать черновик;
- `GET /api/v1/applications/{id}/office-actions/{response_id}/download` — скачать DOCX.

Доступ совпадает с доступом к делу: владелец-клиент, назначенные сотрудники и
администратор. API дополнительно проверяет, что уведомление и все приложения
относятся к той же заявке.

## Известные ограничения

- срок ответа пока вводится человеком и не извлекается автоматически;
- система не отправляет ответ в Роспатент и не отслеживает его доставку;
- для содержательной проверки доказательств нужен отдельный этап извлечения и
  подтверждения данных из каждого приложения;
- черновик не заменяет проверку патентным поверенным или юристом в сложном деле.
