# Product backlog «Регистра»

**Актуализировано:** 28 августа 2026 года.

Это единый рабочий список продуктовых задач. Фактическое состояние уже
реализованных функций описывается в [`current-state.md`](current-state.md), а
крупные этапы развития — в [`roadmap.md`](roadmap.md). Новые идеи сначала
добавляются сюда с проверяемым критерием готовности, чтобы не размножать
повторяющиеся документы.

## Завершено в текущей ветке

| Задача | Критерий готовности | Статус |
|---|---|---|
| Автозаполнение из ЕГРЮЛ | Наименование, ИНН, ОГРН, КПП, адрес, ФИО и должность руководителя появляются на экране проверки и сохраняются между экранами | ✅ |
| Автозаполнение из ЕГРИП | ФИО, ИНН, ОГРНИП и основной ОКВЭД переносятся в заявку; предприниматель автоматически предлагается как подписант | ✅ |
| Восстановление старых результатов разбора | Уже загруженную выписку не нужно загружать повторно: поля восстанавливаются из сохранённого результата извлечения | ✅ |
| Поля актуального заявления | В карточке доступны КПП, страна, способ подачи, ФИО и должность подписанта, дата подписания; обязательность зависит от типа заявителя | ✅, простой случай |
| Корректный официальный DOCX | Используется актуальный бланк; отметки применимых чекбоксов ставятся автоматически, знак размещается в поле (540), описание — в (571) | ✅, простой случай |
| Комплект документов | ZIP разделён на материалы для подачи и памятки пользователя; отдельный перечень товаров создаётся только когда он действительно нужен | ✅, простой случай |
| Заполнение на финальном экране | Недостающие реквизиты, описание и подписанта можно заполнить прямо при подготовке пакета; изображения и условные приложения загружаются там же | ✅ |
| Понятная маршрутизация незавершённости | Для классов и анализа пользователь возвращается сразу к проверке, а не на начальную загрузку | ✅ |
| Юридически корректная подпись | Сервис не имитирует нарисованную подпись: разъясняет собственноручную подпись для бумаги и электронную подпись для электронной подачи | ✅ |
| Фоновый анализ в клиентском пути | После запуска клиент сразу переходит на экран результата, видит этап и прогресс; готовый результат появляется автоматически, незавершённые части можно безопасно повторить | ✅, локальный MVP |
| Автосохранение проверки данных | Изменения основной формы сохраняются с задержкой, пользователь видит состояния «сохраняем», «сохранено» и ошибку; явная кнопка не отправляет повторно уже сохранённые данные | ✅ |
| Подтверждение данных перед анализом | Подтверждение записывается в аудит, сбрасывается после изменения заявки или карточки заявителя и блокирует финальный ZIP, пока сведения не проверены заново | ✅ |
| Переход к незавершённому полю | Сводка на экране проверки показывает, чего не хватает, и прокручивает к заявителю, обозначению или подтверждению классов | ✅, экран проверки |
| Адаптивная кнопка помощника | Кнопка закреплена выше подвала, учитывает safe area, не обрезается на узком экране и не перекрывает основное действие | ✅ |
| Последовательный экран проверки | Пять подписанных шагов идут сверху вниз: заявитель → подписант и подача → представитель → знак и перечень → классы; запуск анализа доступен только в конце | ✅ |
| Переходы между этапами | Направленное появление экрана, акцент активного шага и плавное перемещение к началу этапа; `prefers-reduced-motion` поддержан | ✅ |
| Автоматическая матрица заявления | DOCX различает юрлицо, ИП и физлицо; ОГРНИП подписывается корректно, чужие идентификаторы не подставляются, основные виды знака проверены тестами | ✅, ручная приёмка остаётся |
| Единый справочник применимости | Manifest `1.1.0` управляет полями клиентской формы, Completeness Engine, готовностью ZIP и идентификаторами DOCX с учётом заявителя, знака, выбранного представителя, основания его полномочий, приоритета и способа подачи | ✅, простой сценарий |
| Представитель в конкретной заявке | Клиент выбирает самостоятельную подачу или конкретного представителя, указывает адрес, контакты, основание полномочий и при необходимости номер патентного поверенного; доверенность запрашивается и попадает в ZIP только при подаче по доверенности, а официальный DOCX получает вид и реквизиты представителя | ✅, простой сценарий |
| Production-worker анализа | API и отдельный процесс используют БД-очередь с атомарной арендой, heartbeat, восстановлением просроченной попытки, deduplication key и защитой от запоздавшего worker-а; 8 worker-ов забирают 100 заданий без дублей | ✅ |
| Понятные источники полей | Сервер сверяет текущее значение с извлечённым документом и автоматической подсказкой; интерфейс различает документ, ввод пользователя, предложение системы и будущие поля Роспатента, а при наведении объясняет источник | ✅ |
| Технический baseline персональных данных | Доступ к документам, извлечённым полям, представителям и аудиту ограничен делом; удаление черновика освобождает физические файлы; лишние PII не дублируются в аудите и основном LLM-анализе; фактическая модель угроз документирована | ✅ |
| Современный знак «Регистра» | Единый векторный wordmark используется на входе, в клиентском и профессиональном кабинетах; фирменная разрезная кириллическая «Р» с бирюзовым сегментом собрана в разомкнутое справа кольцо, которое визуально соединяется с остальным словом | ✅ |

## P0 — до платного внешнего пилота

- [ ] Провести постраничную юридическую сверку сгенерированного DOCX с
  актуальной официальной формой на выборке: организация, ИП и физическое лицо.
  **Готово, когда:** юрист подписал чек-лист по каждому полю и условному
  чекбоксу, а регрессионные тесты покрывают найденные расхождения.
  Автоматическая матрица и шаблон ручной приёмки уже подготовлены в
  [`legal-docx-review-checklist.md`](legal-docx-review-checklist.md); осталось
  сформировать три образца и получить подпись проверяющего юриста.
- [ ] Проверить извлечение ЕГРЮЛ/ЕГРИП на разных поколениях выписок ФНС и плохих
  сканах. **Готово, когда:** есть обезличенный eval-набор, метрики по каждому
  полю и безопасный ручной fallback. Измеритель, начальные обезличенные фикстуры
  и проверка безопасного fallback готовы; до пилота нужно собрать и разметить
  корпус реальных документов разных поколений по
  [`registry-extraction-evaluation.md`](registry-extraction-evaluation.md).
- [ ] Утвердить организационную политику обработки персональных данных перед
  внешним пилотом: оператор, основания обработки, уведомление Роскомнадзора,
  договоры с LLM-провайдерами, сроки по категориям и backup. Технический аудит,
  немедленное удаление черновых файлов и модель угроз уже выполнены в
  [`personal-data-threat-model.md`](personal-data-threat-model.md); осталось
  утвердить сроки и автоматизировать плановое удаление.

## P1 — расширение комплекта заявления

- [x] Представитель: ФИО/наименование, адрес, контакты, статус и номер
  патентного поверенного, основание полномочий, реквизиты доверенности и
  корректное условное приложение для выбранной заявки.
- [ ] Несколько заявителей и распределение контактных данных.
- [ ] Конвенционный, выставочный и иной приоритет: вид, дата, номер, страна,
  сроки и подтверждающие документы.
- [ ] Бумажное свидетельство, адрес для переписки, публичные контакты и прочие
  условные поля официальной формы.
- [ ] Коллективные, звуковые, объёмные и иные нетрадиционные обозначения с
  отдельными требованиями к материалам.
- [ ] Проверка доверенности: стороны, полномочия, срок, передоверие и связь с
  подписантом; неоднозначные случаи передаются юристу.
- [ ] Управляемая работа с паспортом физлица: извлечение только необходимых
  полей, маскирование, подтверждение и запрет включения лишней копии в ZIP.
- [ ] Электронная подпись и отправка через разрешённый официальный канал после
  отдельного юридического и технического проекта.

## P1 — удобство самостоятельного клиента

- [ ] Распространить единый статус автосохранения с основной формы на настройки
  льгот и черновик ответа Роспатенту, где это не конфликтует с явным
  подтверждением юридически значимых фактов.
- [ ] Распространить переход к незавершённому полю с экрана проверки и финального
  пакета на пошлины и ответ Роспатенту без потери контекста.
- [ ] Предпросмотр заявления перед скачиванием с подсветкой места каждого
  введённого значения и изображения.
- [ ] Провести пользовательский тест пояснений к МКТУ, приоритету, пошлинам,
  подписанту и приложениям; сократить подсказки, которые не помогают пройти
  следующий шаг. AI-помощник уже ограничен вопросами регистрации знаков.
- [ ] Доступность и адаптивность для 2K/4K и небольших экранов, клавиатурная
  навигация и понятные состояния долгих операций.

## P2 — качество анализа

- [ ] Полный визуальный индекс реестра для изобразительных знаков, а не только
  ранжирование карточек, найденных по словесной части.
- [ ] Юридическая оценка изображения по элементам обозначения без показа
  клиенту технических коэффициентов как готового правового вывода.
- [ ] Расширение и версионирование правового RAG-корпуса, мониторинг изменений
  законодательства и юридический eval-набор.
- [ ] Отдельные проверки однородности товаров, приобретённой различительной
  способности, согласий, дискламаций, НМПТ/ГУ и специальных оснований отказа.
- [ ] Современное визуальное обновление и единая система анимаций после
  стабилизации сценариев: переходы между этапами, понятная обратная связь на
  важные действия, отсутствие скачков вёрстки и поддержка `prefers-reduced-motion`.

## P2 — пошлины и сопровождение

- [ ] Подтверждаемые льготы с перечнем допустимых оснований и документов.
- [ ] Оплата пошлин, загрузка квитанций, контроль этапов и сроков доплаты.
- [ ] Получение номера заявки, статусов, корреспонденции и сроков после подачи.
- [ ] Полный клиентский и юридический контур ответа на уведомления Роспатента с
  доказательствами однородности и приобретённой различительной способности.

## Внешние зависимости

- официальный или договорной источник данных Роспатента;
- разрешённый канал электронной подачи и электронной подписи;
- платёжный провайдер;
- почта/SMS и календарь сроков;
- production-инфраструктура: PostgreSQL, объектное хранилище, очередь задач,
  резервные копии, мониторинг и secret store.
